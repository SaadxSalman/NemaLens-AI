# API Reference

The canonical interactive reference is generated by FastAPI at `http://localhost:8000/docs`. This document explains the intended semantics behind the endpoints.

## Health

`GET /health` is a liveness probe. It must not depend on PostgreSQL, Redis, Qdrant, or a model provider. A separate readiness probe should be added before production to check those dependencies explicitly.

## Query

`POST /api/v1/query` accepts a `QueryRequest`:

- `question`: required, 3 to 2,000 characters; whitespace is normalized.
- `patient_context`: optional, max 5,000 characters; de-identify before sending.
- `specimen`: `stool`, `blood`, `skin`, `water`, or `unknown`.
- `geography`: optional location used for epidemiological filtering.
- `host`: optional host species; defaults to human.
- `include_web_fallback`: controls whether an approved external search connector may be used.

The response is a `DiagnosticReport` with a stable `report_id`, summary, ranked findings, citations, next steps, safety note, generation timestamp, and retrieval trace.

## Upload

`POST /api/v1/upload` accepts a multipart `file`. The current service performs an in-memory type and size gate and returns an `UploadReceipt`. A production implementation should stream to private object storage, run malware scanning, and enqueue parsing instead of using request memory.

Accepted demo content types are JPEG, PNG, TIFF, and PDF. The configured limit is `MAX_UPLOAD_SIZE_MB` with a default of 15 MB.

## Error policy

- `422`: request does not satisfy the typed schema.
- `400`: file policy or business validation failure.
- `401`/`403`: authentication or workspace authorization failure after auth is added.
- `429`: rate limit exceeded.
- `503`: a required provider or search dependency is unavailable.
- `500`: unexpected server error; never include provider secrets or patient data in the response.
